# New-game progression

Traced from the PAL disc (SLES-03556). Addresses are SLES, GAME (`COMMON/GAME.BIN`, load 0x800AD000) or stage overlays (`DAT/STxxT.BIN`, load 0x800E7000).

## Engine mechanisms

- Game-state block 0x8009C7E8: stage +0x10, area +0x11, scenario +0x14/+0x15, start mode +0x0D, difficulty +0x16, load-from-save +0x0C.
- SLES 0x8001392C(type, arg) only starts a screen transition (jump table 0x80010094): 0x02 subtractive reveal, 0x12 cover to black, 0x22 type-2 wipe, 0x26 circle wipe.
- Stage changes use the request block 0x80078D08: +0 type, +4 stage, +5 area, +0x10/+0x12/+0x14 position, +0x16 facing, +0x18 arrival fade, +0x19 exit fade (0xFF none). Type 2 changes stage (GAME 0x800B0420, writes at 0x800B04B8). Type -1 changes area within the stage (GAME 0x800AEC4C, write at 0x800AED6C). Both copy +0x15 to +0x14 and clear flags 0x580-0x65F (0x800C037C).
- Event flags: bitfield at 0x80098538; set 0x800C0558, clear 0x800C0584, test 0x800C05B4.
- Scenes: GAME 0x800C0B0C(id) starts scene `id` through handler table GAME 0x800DC490. Handlers call 0x800C0C5C(camera_stream, timeline). Timeline entries are 8 bytes: phase, step, s16 trigger frame (-1 = callback advances), callback address; 0xFF ends. 0x800C0D70 runs the timeline.

## Game Start

1. DEMO 0x800AD774-0x800AD7B0: stage 0x39, area 0, +0x0C/+0x0D/+0x12-+0x15 = 0, +0x16 = 1; transition 0x26.
2. GAME state 0 (0x800AE7B0): 0x800AE328 game-block defaults, 0x800C0284 clears all flags, 0x800D97B4 difficulty tables, 0x800C35B0 player initialiser (only caller 0x800AE824; struct 0x8008C0A0; HP/items from +0x16 and +0x0D).
3. GAME state 1 (0x800AE848) loads stage +0x10 (0x800BA600).

- The extinguisher is special weapon 0x0F with flag 0x38F, equipped by the new-game initialiser GAME 0x800C37B0; its module is most likely COMMON/PL00R0F.BIN (unverified).

## Flutter repairs and furnishings

- Flag 0xD1 (set by the first-visit scene 0x4C) is the damaged state: the ST06 stage frame `0x800E729C` (GAME table `0x800DC66C[6]`) sets 0x717/0x719 while it is set, which locks the Deck 2 doors to the Living Room and Storage (blocked message ST06:1). Clearing 0xD1 unlocks them.
- Roll's menu (ST04 messages 0x52-0x54 via Talk to Roll): Repairs -> message 0x28/0x29 (cost 2,000/4,000/6,000/8,000 by flags 0x129/0x12A from the fire mission). Yes runs op 0x42 (SLES `0x8004EA14`: wallet below price -> message 0x2B), sets 0xDF, spends zenny (op 0x37) and adds 3000 to save+0x42 (op 0x40, SLES `0x8004E8F8`). ST04T `0x800E7828` then sets save byte 0x7C to 1 and flag 0x134. Op 0x47 (SLES `0x8004ECC4`) compares byte 0x7C against 2/3/4/5; message 0x7C clears 0xD1. GAME `0x800BA420` increments non-zero bytes 0x7C-0x83 whenever a stage >= 8 in a different region (table `0x800DBDA0`, saved as byte 0x12/0x84) is entered.
- Furniture is a placement variant chosen on room entry: ST06T Living Room handler `0x800E73A4` calls GAME `0x800C010C(tile (63,64), 1)` while flag 0xD6 (TV bought, 25,000 zenny) is clear, so the television is absent until bought; Kitchen handler `0x800E7510` does the same for the refrigerator while 0xD4 (5,000 zenny) is clear. 0xD5 (newspaper) spawns an extra actor in the Living Room (unported).

## Roll's development scene

- Roll on the bridge (ST04 actor class 0x60, message 70) chains on byte14 to 71 (byte14 0: Development Room / Never mind) or 72 (byte14 >= 1: adds Move). Both open the prompt message 0x4B in window 1 (op 0x12, SLES `0x8004CD68`: advance 4, open bank message arg1 in window arg0), whose text op 0x41 (SLES `0x8004E950`: byte `0x8009C82D` 0/1/2 selects program bytes +2/+3/+4, 0xFF continues, length 5) picks as message 0x4D, 0x4C or its own, then flag 0xD0 set redirects to 73/74 (adds "Talk to Roll"). "Development Room" redirects to message 0x4E, which sets flag 0x6FD and waits (op 0x2B).
- ST04T `0x800E79B4` tests and clears 0x6FD, then GAME `0x800C0B78(0x30)` starts scene 0x30: GAME table `0x800DC490[0x30]` = `0x800C0530` calls the stage hook `0x80078DC0` = `0x800EE228` (states `0x800F4300`: `0x800EE264`, `0x800EE454`, `0x800EE4B0`). The scene's menu state machine is table `0x800F41CC` (main `0x800EAACC`, development `0x800EBAB0`, change weapon `0x800EADD4`, improve `0x800EB1FC`); its 74-message bank is at `0x800F25C4` and shares op 0x2E (SLES `0x8004E00C`, signed pen-x advance) and op 0x3D (SLES `0x8004E73C`, item name from context+0x6C) with the other banks.
- Main menu: Development / Change Weapon / Improve Weapon / Cancel (message 0). State 0 announces the Roll price tier once: flags 0x190/0x191/0x192 remember the last tier of byte `0x8009C82D` (0 cheap, 1 normal, 2 broken tools); messages 26 (tier 0, flag 0x190 clear), 27/28 (tier 1 after 0x190 / 0x192), 29 (tier 2).
- Development (`0x800EBD34`): lists the owned items 0x408-0x437 (event flags 0x400+n) and Cancel. The selected item is matched against the 12-byte records at `0x800F4088` (result, first, second or 0xFFFF, kind, first hint, second hint). A record whose other item is missing says the hint message of that item (16 prints the item name, 40-67 describe the part); kind 0 (special weapon, 14 records) and kind 3 (two items) ask "combine with" (message 15), kind 1 (one item) asks message 17, kind 2 (notes, 6 records) translates the selected Mechanic Notes into the result at once with message first_hint (68-73). Confirming sets the result flag and clears the used flags; messages 23 (weapon: try it) or 24.
- Change weapon (`0x800EAE9C`/`0x800EB084`): owned special weapons 0x383-0x393; Yes writes the id to player+0x18E and shows message 6.
- Improve (`0x800EB258`, `0x800EB4AC`, `0x800EB66C`): stat levels are bytes player+0x1F4+8*weapon+stat (attack, energy, range, rapid, special). `0x800EDBA4` returns -1 at the cap (GAME `0x800DC8E8`, 5 bytes per weapon), else the u32 at cost table `0x800F4040[weapon]` + 20*level + 4*stat, minus a tenth for byte45 = 0, plus a tenth for 2, at most 9,999,999. Messages: 1 stat menu, 3 price, 5 wallet, 7 done, 8 cap, 9 too poor.

## Forbidden Island capsule

- ST49 scene 0x18 (`0x800E72B0`) selects its camera and timeline at initialization using flag 0x5C1. Clear: camera `0x800EC850`, timeline `0x800ECB20`, seven callback steps, arrival ST10:0 at `(2048,-881,-13312)`, yaw 0x800. Set: camera `0x800ECA44`, timeline `0x800ECB60`, four callback steps, arrival ST04:0 at `(264,-1,320)`, yaw 0. Both requests use mode 2 and arrival fade 2. The per-frame trigger `0x800E7270` tests 0x5C0 or 0x5C1 without an area condition.
- While the Flutter is airborne at Forbidden Island (story byte below ST10's `minimum_save_byte14` 2) the port loads no parked exterior and instead draws the ST49 clear-branch strips and rings (`flutter_storm.gd` driving `native_stage_backdrop.gd` at 25 Hz from the view camera) outside the windows; the screen-space wave is omitted. This is a user-requested presentation choice: ST04T-ST07T bind null background tables to GAME `0x800BEF64` in every area, define no weather fields, and contain none of the ST49 backdrop actor records, so no original source for it was found.
- ST07 area 1 (Flutter hangar) parks the capsule: ST07T stage-frame table `0x800E8B28[area]`, area 1 frame `0x800E72FC`, spawns record `0x800E8B10` (class 0x6D, resource `0x6D20`, raw `(0,152,176)` yaw 0x400) once through `0x800E7364` whenever save byte14 is nonzero. No event flag gates it and its update is a no-op, so it stays in every story state. `tools/models.py stage-actors --stage ST07` exports it as per-state scripted actors (constructor `0x800E74E4`, control 2).
- Records `0x800EC788`, `0x800EC79C` and `0x800EC7B0` are procedural pool-0x60 class-0x12 renderers, rather than missing mesh resources. Variants 3 (`0x800EA188`) and 5 (`0x800EAD08`) draw sprite strips; variant 2 (`0x800E9B34`) draws four rotating rings of 32 billboards using heights `0x800ECD2C`, radii `0x800ECD38`, sizes `0x800ECD44`, UV table `0x800ECD50` and palettes selected by `0x800ECC20`. Record `0x800EC7C4` belongs to pool 0xA0 class 9 (`0x800EB2B0`): an additive 11-by-9 grid of textured quads, using page 0x2E, CLUT 0x7C92 and sine-modulated vertex brightness. Its profile at `0x800ECDA0` supplies base 48, amplitude 16 and phase velocities `(320,-240)`.
- Native emulation verifies the departure and return requests over 1302 and 865 updates respectively. A silent Redot GPU probe checks both runtime branch selections, retained records, procedural geometry, textures and the waveform's first native GPU packet positions, UVs and vertex colours. The complete travel and cinematic flow still requires a separate runtime check.

## Forbidden Island aftermath

- ST1D scene 0x29 requests ST1C area 0 at story byte 1. The ST1C frame function `0x800E72A0` starts GAME `0x800C0B0C(0x13)` once (latch `0x8009BE08`) while the area byte is 0. Scene 0x13: handler `0x800F027C` dispatches on context byte +4 through `0x800F64F0` (initialise `0x800F02E4`, run `0x800F04B0`, exit `0x800F053C`), camera `0x800F5504`, timeline `0x800F62A0` (callback steps from `0x800F06FC`). It opens no message window; its sound is XA only, through SLES `0x8001B864` (stream 0x31 at tick 3, 0x3D at about 2555, 0x5C at about 7449; `0x8001B714` only queues the seek and `0x8001B9A4` is the pair). - Area sequence driven by the timeline (type -1 requests): 0 -> 2 -> 5 -> 0 -> 1 -> 0 -> 2 -> 4 -> 3 -> 4 -> 3, fades 0x02, 0x12, 0x01, 0x1A, 0x0C, 0x14 and 0x02. The probe (stream waits shortened to 120 ticks) reaches the exit at tick 13577: request ST3E area 3 at (576,-1,-144) facing 1024, mode 2, arrival fade 2. - Mega Man takes part in scene 0x13 through the player struct: control `+0xA0` runs 0x80-0x87 (one-record clip 0x80 at the start, looping 0x85 in area 1), record `+0x9C`, position `+0x10..+0x18` and the render flag (byte 0, bit 1; clear in the area 1 shot). - ST1C's first type-0x0C section starts with a player-clip block (first word `0x80000FAC`, bit 31 set); the model table follows it (count 8 at `+0xFAC`). `runner_host.gd` `bank_address()` skips such a block.
- Scene 0x13 runs areas 0, 2, 5, 0, 1, 0, 2, 4, 3, 4, 3 and ends at tick 13579 in a headless run. ## Original-code runner

Boss fights, story scenes, dungeon enemy classes and special weapons are run from the original PS1 code instead of being ported one by one. The shared engine services are implemented once (high-level emulation) and everything else executes as translated code.

Design: ahead-of-time static recompilation (`tools/models.py runner`, `MipsRecompiler`/`MipsEmitter`) into GDScript, not a GDScript interpreter. Functions are found by flood fill from the stage overlay (after each return, stack-frame prologues, call targets and every code pointer) and from the engine roots; jump tables are resolved from the preceding `sltiu` bound; delay slots are reordered against the branch condition; registers are `R[n]` in one `PackedInt32Array` (HI/LO are 32/33), RAM is one `PackedByteArray` with the mirrors collapsed by `& 0x9FFFFF` (scratchpad at 0x800000), blocks inside a function are a binary dispatch over `pc`. Reasons: no per-instruction fetch/decode in GDScript (the interpreter alternative costs an order of magnitude more per tick), no native code (the web export runs it unchanged), deterministic integer arithmetic, and the output is regenerated from the disc so nothing is committed. Units compile from source at run time (`GDScript.new()` + `reload()`), about 4 s for the shared engine unit (1.5k functions, 5 MB source) on the desktop; all thirty boss-gauge stages translate with no unresolved target (`manifest.json` lists 42 hardware-bound stubs and one unresolved jump `0x800640F0` in a debug path). The GTE (RTPS, RTPT, MVMVA, NCLIP, OP, SQR, AVSZ3/4, GPF, GPL) is `scripts/runner/gte.gd`.

Services (`scripts/runner/hle.gd`, `hle_bios.gd`, `runner_bridge.gd`): message windows (SLES `0x80048474`/`0x800489A0`/`0x80048764`/`0x80048944`) go to the port's dialogue; transitions `0x8001392C` to the fade overlay; sound `0x800203F4`/`0x80020384`, music `0x800201B0` and fades `0x80020984` to `game_audio.gd`; the view call `0x80015B6C` supplies the scene camera; the boss gauge registration `0x800BBDD8` binds the port's gauge; BIOS A0 `bzero`, `memcpy`, `memset`, `rand`, `strcmp`, `strncmp`, `printf`; the render submission `0x800B0314`, critical sections and the audio engine's VBlank bits are no-ops. Everything else (actor pool, class state tables, floor and wall collision from the stage's own map data, hit words, flags `0x80098538`, story bytes, scene timelines, camera streams, the 25 Hz LCG) runs as original code. The original player update `0x800C3CB4` runs only while a scene drives the player; the hit resolution `0x800C42F4` runs always and writes the player's hit words `+0x1D4`/`+0x1E4` (attacker position `+0x1DC..+0x1E0`), which the host forwards to `player.take_hit`.

Host (`scripts/runner/runner_host.gd`, `runner_actor_view.gd`, attached from `native_props.gd` after the Icefield encounter): opt-in per stage through `RUNNER_STAGES[...]["attach"]` (story byte, areas, actor classes the port draws itself). Every tick (25 Hz): the port player's position/yaw and ground contact enter the runner's player struct (`0x8008C0A0`), port flag changes enter the runner's flag bytes and runner flag changes (and the pending story byte `0x8009C7FD`) leave into `native_context`, the original frame runs (`0x8001D858`, `0x800AEB30`), actors of the pool (`0x8007A140`, 24 x 0x16C) become `RunnerActorView` bodies (model chosen by the mesh pointer at `+0xA4` against the archive table at `0x80124800`, scale from mesh `+0x30`, control `+0xA0` and record `+0xA3` drive `NativeAnimation`, position `+0x12/+0x16/+0x1A`, yaw `+0x2A`, hurtbox from `+0x58`, health `+0x70/+0x72`), hits taken by a view are OR-ed into the actor's hit word `+0x14C`, a scene (`0x8007CEC0`) hides the HUD and drives the player, camera, messages and fades, a stage change of the runner calls `native_scene_area`, a type-2 request block (`0x80078D08`) becomes a stage transition route.

Verified: `runner-verify` (977 functions, 3683 random cases in Unicorn and the engine: registers, RAM and scratchpad digests identical; 1120 GTE cases identical within the divide's rounding) and `runner-pilot` (ST1D: scene 0x28, boss spawn at tick 375, scripted hits, death at 1156, flag 0x682, scene 0x29, request ST1C area 0 at (1755,-594,4702) facing 1894, arrival fade 10, no unresolved targets; fight ticks mean 14 ms, p95 16 ms, max 25 ms on the desktop editor build; 40 ms available at 25 Hz). The same flow runs in the real gameplay scene headless (`gameplay.tscn`, ST1D area 1, story byte 1, flag 0x681, scripted Buster hits from the port): scene 0x28 with the earthquake and radio message 10, area change to ST1D area 2, boss gauge bound to the view, 1760 health depleted, scene 0x29, `stage_transition_requested` with the route above; boss contact damage reaches the port player.

Smoke (story byte 1, area 0, 100 ticks, no unresolved target) for all thirty boss-gauge stages; ST12 area 1 and ST13 area 0 spawn dungeon enemy classes (0x2A/0x1B, 0x31) at 8-15 ms per tick.

Not done: the class-52 variant-0 walkers and class-36 spawners of ST1D (they spawn from the same code once the story byte/area allow it; no run reached them), per-class visuals other than models (sprite/effect records emitted through the renderer `0x800390EC` are dropped; `native_effect.gd`/`rocket.gd` would consume the captured records), the player's pose in runner scenes (the port keeps its own animation), special weapon modules (`PL00R*`) and grab enemies (the player struct is a puppet; grabbing needs the grab-state player API), runner-driven stages other than ST1D (no `attach` rule: each needs its story/area rule and its port-drawn classes), messages in other windows than the single dialogue box, sound positions beyond the source point, XA playback requests, and the web packs (`runner-core` and `runner-STxx` groups are generated by `tools/export_web.py` and fetched by `asset_store.gd`; the web build itself was not run). The first load of a stage compiles about 5 MB of GDScript on the main thread (about 4 s).

### Runner follow-up

- Load: the stage unit compiles on a worker thread started by `runner_host.gd` at attach; the gameplay frame time stays at 22 ms (headless) while it compiles and the runner starts when the thread ends. The initial `begin` (new-game initialisers, stage and area set-up) takes about 170 ms on the main thread. The unit was not split per module.
- Audio: `0x8001B9A4` (XA descriptor) plays through `gameplay.play_voice`, `0x8001AF94`/`0x8001AFD0` report the port's voice state and `0x8001BA44` fades it. Message requests from several windows run one after another in the single dialogue box.
- Player: grabs `0x800CFF88(actor, reach, mode)` check the box against the runner's player struct and call `player.begin_hold`; the hold ending sets player state (+9) and +0x2AC back; `0x800D008C` is replaced by the port's hold. - Effects and sprites: the render phase `0x800B0314` is a list of independent children (`0x80026DA0` map polygons, `0x8003B4FC` shadows, `0x800390EC` effect record renderer, `0x800230F0`/`0x800243E8` windows and HUD); running it whole follows data as code, but `0x800390EC` alone works. `Session.render()` resets the ordering table like `ClearOTagR` (0x1000 entries at `0x1F800048`), runs `0x800158D4` (swap to the scratchpad stack), `0x800390EC` and `0x800158F8`, and `runner_gpu.gd` walks the table (polygons: vertices, colours, UVs, tpage, clut, semi-transparency). GTE state the main loop sets is written at begin: H 0x180 (SLES `0x80011164`), offsets 160/120, DQA/DQB/ZSF from InitGeom. The camera call `0x80015B6C(focus, distance, yaw, pitch, roll)` takes raw (1/256) focus integers; a2 is the yaw and a3 the elevation (eye = focus - distance * (sin yaw cos pitch, sin pitch, cos yaw cos pitch) in raw axes, y negative up); the host replaces the arguments with the port camera's pose outside scenes (focus = eye + forward * 1024), and the runner's resulting eye and view direction equal the port camera's within 1 raw unit and 2e-5 (checked headless). `runner_effects.gd` draws the packets as polygons on a canvas layer (centre = viewport centre, scale = viewport height / (2 * H * tan(fov / 2)), textures decoded from `STxx.vram.bin`, blend modes from the tpage); the drawing was not looked at (headless only). In the ST1D fight the renderer yields 16 to 160 quads per tick around hits. The 99 type-0x3E quads seen without the camera set-up are not actors.
- Attach rules: `models.runner_attach_rule` derives, for every runner stage, the actor classes the port owns (scripted/NPC/mine tables, dungeon enemies, mine lifts), the scene ids the port plays from `scene_XX.json`, and `enabled` from `models.RUNNER_VALIDATED`. The host kills actors of port-owned classes after each tick, hides door models (flags 0x161/0x261/0x361), does not start port-played scenes (`0x800C0B0C` hook), keeps the runner's area and stage requests only while a scene runs (or the port itself requested an area), and ignores attach calls for rooms other than the gameplay's current level.
- Room streaming: in streamed dungeons the host attaches to the active room (`room_stream.room_root(stage, area)`, whose position is the layout offset, so `to_local` stays in stage coordinates). A room change reaches `level_loaded`, which frees the previous room's actor views and asks the original for the area change through the request block; neighbouring rooms are never attached, so only one area runs. Checked headless for the 23 enabled stages (attach, 500 ticks, no faults, views parented to the room) and by switching ST50 through its rooms (runner area follows 0, 1, 2, 3; no views left in the old room).
- Effect state the main loop sets, found by comparing against NativeMachine: the 64-entry sine tables at `0x800965D8`/`0x800968D0` (built by SLES `0x80011294`, copied from `0x80073E4E`/`0x80073E4C` at begin) size the billboard corners, so without them every effect quad collapsed to a point; the camera matrix at scratch `0x1F800014` is overwritten by later actor code, so `Session.render()` replays the last camera call first. `runner-verify` replays a fight snapshot (RAM, scratchpad, GTE) in NativeMachine with its Python GTE and compares the 36 ordering-table packets (command and vertices, draw order) and all 176 GTE operations (command, input registers, output registers): both identical. An earlier report of 36 against 18 packets was a bug in the check's own table walk (it read the top of a 1024-entry table instead of 4096).

The comparison is record class against spawned class, not against a separate table of expected counts.
- Runner stop: on any unresolved target the host frees its views, ends a running scene and stops ticking, with one error naming the stage and area, instead of continuing on corrupt state.
- Special-weapon modules: `COMMON/PL00P000.BIN` and `PL00Rxx.BIN` are sequences of type-1 sections (a 0x30 byte header: type, size, sector count, load address; data; padding to 0x800). PL00P000 loads at `0x80110800` (control records), `0x80113A00` (meshes) and `0x80123000` (control table for controls below 0x60, read by SLES `0x8003F2A8`); a module loads its code at `0x8010A000`, data at `0x80113340`, tracks at `0x80121E20` and the control table for controls 0x60-0x6F (control 96 is the firing animation) at `0x801246B0`. The exporter translates every module (`manifest["modules"]`) and writes the sections; `Session.begin` places the PL00P000 sections, `Session.equip_weapon(id)` loads module `PL00R(id-1)` (the unit replaces the previous one; a stale call into the module window deactivates the calling actor instead of faulting) and writes the weapon's tank record (`0x800DCA08 + 8 * id`: refill, cost, capacity). Firing is driven by the port's shot sequence (`special_shot.gd`, arm model and tank from `assets/player/weapons/weapon_XX.json`): its bullet script `scripts/runner/runner_bullet.gd` hands the muzzle and heading to `RunnerHost.fire_weapon`, which on the next tick writes the muzzle (player `+0x164`/`+0x16C`), yaw (`+0x2A`), weapon (`+0x18C`) and stat levels (`+0x1F4 + 8 * id + stat`) and calls GAME `0x800CE5D4`; that routine allocates the launcher actor of the weapon's class (record byte 7 of `0x800DC978`) when player `+0x13C` bit `0x10` is set, and the module's class code takes over. The original firing states (`0x800CE808`, `0x800CEA04`, `0x800CEB20`, `0x800CEC94`) are no-ops so that they do not clear the flag. The player's own hit reaction `0x800CB4DC` is a no-op so that its hit words reach `take_hit`. Driving the same weapons through the original update with pad words (`0x8009BEC0 + 0x24/0x28/0x2C`, special mask `+0x130`, slots `+0x18C`/`+0x18D`) also works and was used to trace them.
- Special-weapon results headless in ST13: the Machine Gun Arm (id 13, registered in `player_controller.gd` `SHOT_BULLETS`) spawns its class 0x0C launcher and the class 0x11 bullet that flies 288 raw units per tick and takes 20 health (56 to 36) from a runner-owned enemy, and a port-owned test body received one 20-damage hit per shot. Run in isolation through the original pad path, ids 3, 4, 7, 9, 13 and 16 consume tank at the fire pose (ids 8 and 12 cost 1 per tick and are hold weapons); ids 3, 4, 7, 9, 13 and 16 are registered in `SHOT_BULLETS`. Their launchers (and the Machine Gun Arm's bullets) register attacks through two SLES functions, both hooked: `0x800427A0` (segment) and `0x80042704` (point or short attack: start in `a0`, end x and z at `a1+4`/`a1+6`, damage in the low 12 bits of `a2`, shot word with the `0x40000` player bit in `a3`; the explosion records of ids 3 and 16 are zero-length). Ids 12 (Shining Laser), 17 (Drill Arm) and 8 (Vacuum Arm) are hold weapons: their launcher state (`0x8010A108` in the module) lives only while player `+0x13C` bit `0x40` is set and the pad held word `+0x10E` (copied from `0x8009BEC0+0x28`) has a bit of the fire mask `+0x130`. The host (`HOLD_WEAPONS`, `_hold_weapon`) sets those fields every tick while the port's special button is held and releases them otherwise, and skips a second launcher while one is held. Ids 12 and 17 then hit every tick (the Drill Arm only at about 1.5 m). Vacuum Arm: the launcher sets player `+0xCA` bit 2 while the tank lasts and registers no attack; every pickup actor then runs GAME `0x800D15B8` (called from the pickup update `0x800D0DFC`): inside the range given by the range stat (`0x800CF440`, table `0x800DCCC0`, raw units: 2047, 4095, 8191, 32767 by level) it moves toward the player by (pull stat + 1) * 128 raw units a tick (stat 4), or lands on the player at pull level 3. `_vacuum` applies exactly that to the port's pickups once per original tick. Blade Arm (id 11, module `PL00R0A`, handler `0x800CEC94`): the handler is the combo state machine on player `+0x13E` and it runs unchanged. `special_blade.gd` is the shot controller (`SHOT_CONTROLLERS`); the host (`_combo`) calls the handler once per original tick with the animation frame the host counts (`+0x9C`, reset when the control changes), the finished flag (`+0x9F` = -1 at the clip's end: control 96, 97, 98, 99 last 12, 12, 26 and 6 ticks), the press (`+0x110` against the mask `+0x130`) and the tank (`+0x19A` by the cost `+0x198`). The handler answers with the next control (`+0xA0`, played by the controller as `clip_09x`), keeps `+0xC8` non-zero while the blade swings, raises `+0x13C` bit `0x10` at pose 2 (the host then spawns the launcher through `0x800CE5D4`) and ends at phase 9. A press during the first swing (frames 2 to 11) pays one shot and continues with control 98 (jump slash), then 99; no press ends with control 97. The jump slash sets `+0x50` and a vertical speed `+0x3A` that grows by `0x30` a tick; the port's player stays on the ground, so the host clears `+0x50` when the integral of `+0x3A` returns to zero (17 ticks after take-off), which is what lets the handler land the combo. The handler's speeds (`+0x38`, `+0x3A` negative up, `+0x3C` negative forward, in 1/4096 m per original tick: the game applies them through `0x800CD084` and `0x800417AC`, which rotate the s16 vector by the player yaw and add it to the 16.16 position) are applied to the port player each physics frame through `move_and_slide` in `special_blade.gd` (`_move`), forward along the shot heading, so walls stop it: the first swing lunges about 1.1 m, the jump slash rises 0.34 m and carries about 3 m forward; the port clip is held at its last frame until the handler ends the swing. The launcher registers a `0x800427A0` segment (word `0x440060`, 96 damage a tick) from the two points the engine keeps at player `+0x4A8` and `+0x4B0` (the module only reads them: the blade extends 352 raw units from `+0x4B0` along their direction); the writer is the per-bone transform routine `SLES 0x80040624`, which stores a bone's world position as three s16 at player `+0x490 + 8 * bone index` (`0x80040760/80/A0`), so `+0x4A8` is bone 3 and `+0x4B0` is bone 4 (the equipped arm's chain is bones 2 to 4; bones 4 and 7 are the two hands, which is how the Lifter anchor `0x800CFC0C` adds `+0x4B0` and `+0x4C8`), and the host supplies the port skeleton's Bone_03 and Bone_04 world positions. With them the blade reaches enemies up to about 1.6 m ahead. Shield Arm (id 10, module `PL00R09`): the sequence handler table `0x800DCD08` has no entry for it, because the player code (`0x800C9F44`) sets the special flag `0x13C & 0x1000` and stays in its normal state instead of entering a special sequence; the module has no animation bank, so it exports no clip. `equip_weapon` points the empty entry at the no-op handler `0x800CE808` so the launcher can spawn: a bubble at the player (record flag `0x80000`, 40 damage a tick, tiny radius) that damages enemies touching it for 7 ticks. The port spawns it with the shot sequence without an animation (`special_shot.gd`, empty clip) centred on the player. It does not block anything: nothing in the player's hit path (`0x800CB4F0` and the damage routine `0x800CB678`) or in the resolver tests weapon 10 or the `0x1000` flag, the category matrix at `0x8006B47C` gives the bubble (category 1) no contact with the enemy attack categories, and in the Forbidden Island boss fight the hits on the player came on the same ticks with the bubble respawned every 6 ticks and without it. Attack registration: `0x80042704` stores its third argument at the record's `+6` (category) and its fourth, the attack word, at `+8`; the attack word's low 12 bits are the damage and the upper bits the hit flags (`0x40000` player shot, `0x80000` player melee). The resolver reports a hit by writing the struck body's own record word (`0x20008` for an enemy body) to the word the registration's owner argument points at (the launcher's `+0xDC`), which is how missiles and bullets detonate; the bridge does the same after a port body is hit (`HIT_FEEDBACK`). The original hits every tick while a record exists and the resolver adds only the defender record's own damage (`0x800434A4`), so no falloff or cooldown is needed: id 16 deals 144 to a port body as to a runner enemy. Id 15 (Aqua Blaster) stays with the port's hose and id 2 is the Mega Buster. Item names and ids match `assets/shops/items.json` (0x380 + id) and `development.json` weapons 3 to 17. Switching module while another one's actors live makes those actors deactivate themselves.
