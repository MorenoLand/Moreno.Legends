# Original menu rendering
`tools/ui.py` decodes title art from `COMMON/TITLE.BIN`, menu frames from `COMMON/SUBSCN.BIN`, and the font from `COMMON/INIT.BIN`. Generated images and the bitmap font stay in the ignored `assets/menu` directory.
DEMO `0x800AE0D0` draws three untextured Gouraud quads across a 640×480 viewport: RGB `(69,71,255)` from Y 0–128, a gradient to `(207,255,255)` over Y 128–352, then the latter color through Y 480. Source fade multiplies each channel by `fade/128`. `title_background.png` renders these source colors without PS1 dithering.
The logo occupies `(48,32,544,240)` and uses five adjacent 8-bit strips with CLUT `0x7DC0`. DEMO `0x800AE584` draws four 216×40 entry images at X 212 and Y 272, 312, 352, 392. Selected images use page 10 / CLUT `0x7C00`; unselected images use page 11 / CLUT `0x7C40`. The selected third PAL image reads TRAINING while the unselected image reads TUTORIAL. The cursor uses page 10 / CLUT `0x7C01`, UV `(224,0,32,32)`, with X 172 plus a native sine offset and Y 276 plus the selection offset.
Original DEMO instructions were executed to capture 23 primitive records, stored locally as `build/menu/native-title-primitives.json`. These confirm the background, logo and selection coordinates. The port preserves vertical scaling and centers this layout in wider windows.
The original 12×12 glyph UV table is at SLES `0x800682C4`, with variable advances at `0x8006B8F8` and baseline offsets from `0x800498CC`/`0x80049B24`/`0x80049CFC`. INIT font pixels occupy VRAM X 960–1023 and Y 256–511, overlapping the palette region; the palette section at file `0x8800` must load after the pixels. The exporter emits a bitmap font from the source digits and Latin letters. Pause controls use these glyphs and cropped SUBSCN frame textures; their PC actions are Resume, Options and Main Menu, rather than the full original equipment interface.

The Options screen uses the ninety original SUBSCN primitives and palette atlases. Controller A/B/C remap joypad bindings, View controls mouse inversion, and BGM/SE control separate audio buses. New PC settings default to Normal mouse look; stored choices are preserved. Set Screen offsets UI canvas layers, not the 3D output. Controller Select remains disabled until its seventeen-state recommendation dialog is ported. Lock-on and vibration settings are stored, but their complete gameplay behavior remains unported. Options and Load Game now share the original repeating gear backdrop; the common footer remains unported.

## Load Game and persistent saves

SLES `0x80050C20` emits the gear background as a 21×16 grid of sixteen-pixel sprites. The repeating 64×64 tile uses TITLE texture page 13, CLUT `0x7F92` and UV `(48,32)`. Its origin is `(effective_tick&63)-16` on both axes; high-resolution single-buffer mode halves the source tick. The exporter records this in `shared_menu_background`.

The native Load Game window bank is DEMO RAM `0x800B116C`, file offset `0x419C`. SLES `0x80048474` → `0x800490D8` → `0x80049F00` renders its windows. Bank entries six, zero and four supply the header, prompt and selector; each frame has thirty original GPU packets. Their body rectangles are `(15,32,79,23)`, `(41,77,239,23)` and `(80,141,161,55)`. The PC save list expands the selector frame and replaces the card-slot prompt.

Pause-menu Save Game writes a new version-one JSON checkpoint through Godot's application storage. Continue lists those files newest first, including room, date and health. Checkpoints contain stage/area identity, player position and yaw, camera angles, current and maximum health, defeated actor IDs and explored minimap cells, plus zenny, play time, inventory, equipment, special weapon, per-stage event and map state and the native context (story byte, event flags, shop stock, Roll's development levels). Numbers are restored to integers and event-flag keys to integers when a save is read. Item ownership is the event-flag bit equal to the item code (GAME `0x800C0558` sets, `0x800C05B4` tests; bitmap `0x80092538`), so dialogue `0x26`/`0x27` give and consume items; `scripts/state/item_flags.gd` merges those flags with the inventory (codes `0x383–0x451`). The original ITEMS page (SUBSCN `0x801D9304`) lists Items as codes `0x400–0x451` and Key Items as `0x3D0–0x3FF`. Play time is the word at `0x8009C808` (game-state block +0x20), shown by the Status page via SLES `0x8004D5B8` as h:mm:ss. GAME `0x800B0864` adds the per-frame VSync delta `0x1F800005` (50 Hz units) at the end of the stage state machine `0x800AEB30`, which runs through gameplay, cutscenes and stage-load steps but not in the pause, save or game-over modes, and clamps it at `0x0112A87F` (99:59:59). A second counter at +0x24 is incremented the same way. Live projectiles and actor attack phases are not serialized. The loader prepares a replacement scene before discarding the existing session; malformed or unsupported saves cannot be selected for loading.

## Friendly dialogue cameras

Normal request kind `0` and Data's kind `2` use the same friendly-talk callback: GAME `0x800BDBF8` indexes `0x800DC45C` with the signed high half of the request kind, selecting `0x800BDC28` for both. Every friendly request saves/binds and restores the talk camera. FB15 supplies each conversation's close-up framing; a message without that command keeps the existing view. Request bit `0x10` clears the actor-rotation pointer at `0x800BE44C`, suppressing the turn toward the player, while the position pointer and camera path remain active. The runtime therefore listens for camera commands on all NPC conversations, including those that suppress actor facing.

The original Data request passes the actor position through GAME `0x800BE2E0` / `0x800BE39C` to `0x800BDD10`, which calls SLES `0x80016958` to save the current camera focus and orbit and bind the target at camera `0x8007D010+0xE0`. The local recomp checkout has setup/framework sources; these game routines were traced read-only from the project's PAL disc binaries with Capstone.

Data's ST04 entry `180` and ST08 entry `240` contain FB15 bytes `01 0000 0080 0000 0130 0020`. SLES `0x8004CF14` decodes each pair big endian: mode `1`, yaw `0`, pitch `128`, roll `0`, orbit distance `304`, focus height `32`. SLES `0x80016560` adds the player-to-target bearing to yaw, raises the target focus by `32/256`, and positions the camera on the player's side of Data at distance `304/256` and pitch `128/4096` turns. BC is focus height; C0/C2/C4 are angular values, not XYZ offsets. The eye formula is native focus minus distance times `(sin(yaw)*cos(pitch), sin(pitch), cos(yaw)*cos(pitch))`.

The transition interpolates focus, distance and shortest-arc angles over eight camera updates, with fractions `1/8` through `8/8`. GAME `0x800BDE44` calls SLES `0x80016A00` when the interaction closes: mode `0x102` restores the saved view in eight updates; cancelled mode `0x202` takes one. The adapter uses the project's existing PAL 25 Hz cadence and native-scene projection, starting from the current Godot camera. Blank terminal message entries preserve pending commands so FB15 and player visibility execute even when Data has no story text. The prior camera and player visibility return when the menu ends.

## Startup and attract scenes

SLES `0x80012D7C`–`0x80012F28` loads `COMMON/LOGO.BIN` and draws the retail CAPCOM logo at `(48,192,544,96)`, with fade steps of four and a hold counter of 180. The next native scene is ST02 area zero in engine phase four. The title uses its original PRESS START and copyright sprites; the prompt blinks in 32-update phases.

The title's idle threshold is `(3-titleFrameBufferCount)*256`, or 512 updates with the high-resolution title's single buffer. DEMO `0x800AD308`–`0x800AD5FC` cycles ST02, ST50, ST22 and ST51 as engine scenes. The whole local data track contains no standard STR headers or XA video-submode sectors; the XA archives contain audio, not prerecorded opening or attract videos. `tools/disc.py --cue "<disc.cue>"` records this audit locally. The original engine cinematics and replay input streams remain unported; startup logos and the title gate do not replace them.

## Scene entry and camera control

ST1E finale `0x0D` is requested only after timeout/HP completion (`0x800E75E8–0x800E75FC`, `0x800E7804`, `0x800E79C4`, timer helper `0x800E7B88`) or Kitchen fire count zero (`0x800E7A44–0x800E7A60`, setting flag `0x129`). Its eligible rooms are exported as `completion_areas`, distinct from stage-entry triggers. Previously the generic entry dispatcher queued the finale immediately on Game Start, hid the player/HUD, and failed to find a generic `scene_0d.json`. A full main-host Game Start → native ST39 skip → ST1E probe reproduced that failure, then verified visible player/HUD, active controls, no pending finale and no dispatcher error after correction. Failed scene setup now restores the prior visibility snapshot, including an intentionally hidden player.

Gameplay mouse input is accepted only while its camera owns the view and movement/control is active. The prior input handler rotated the hidden gameplay pivot during native dialogue/cutscenes, violating the saved orbit restored by SLES `0x80016958`/`0x80016A00`. A rendered ST08 probe applied mouse movement during talk: before correction, returning moved the saved view by 0.521 m and changed its basis; after correction, actor record `0x800F2684` returned the identical view and normal gameplay mouse input remained active. Scene `0x4F` completed from all four cardinal camera angles with its returned camera within 0.00011 m of a fresh normal-camera calculation. These scene fixtures advanced native ticks directly; their original callback order and normal fade/dialogue paths were retained.

## Lab inspection contacts

ST08 area 1 selects placement 28's collision variant 1 when save byte `0x14` is nonzero: ST08T `0x800E75BC–0x800E7618` checks that byte and calls GAME `0x800C010C(tile (63,64),1)`. Variant 0 has 23 records, including contacts `0xC005`/`0xC007`; variant 1 has 21 records and neither inspection contact, while both variants retain the same 347 geometry quads. The runtime applies the selected physical records and checks the same availability before showing or invoking their Use prompts.

Full main-host ST08 lab probes verified phase bytes 0, 1 and 255: inspection 5/7 works only at zero, and placement 29's contacts 6/8/9 remain available in all three cases. Message 5 describes the half-finished dropship; message 7 describes its painted part and natively redirects to message 4. Only `map_interactions` and `native_floor_collision` were refreshed in the production metadata; existing gate/door bindings and other manifest fields were preserved. NativeFloor's predicate dependency on NativeProps compiled and executed through the actual project/autoload context.

The pause Status panel reads location, zenny, play time and the equipped special weapon from the live game state. The Equipment page takes its Buster stats from the original Equipment screen: SUBSCN `0x801DE3B4` sums the equipped part records of table `0x801E23D4` (8 bytes per part, index = item code - `0x394`, columns attack/energy/range/rapid/special) into player state `+0x204` and clamps each to 7; `tools/ui.py` exports the table into `assets/menu/status.json` (`buster_parts`). The Map page draws Flutter deck plans from `assets/minimap/Flutter/` (see `docs/map_format.md`).
